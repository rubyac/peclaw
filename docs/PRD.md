# Industry Intelligence + PE AI Workbench

## V1.0 技术产品需求文档（PRD + 技术架构 + 数据模型 + 开发计划）

**文档版本：** V1.0
**文档状态：** 开发基线
**产品类型：** 面向 PE/VC 投资机构的产业情报与 AI 投资工作平台
**首期示范行业：** 半导体设备、先进封装
**目标客户：** 中国境内 PE/VC、产业投资机构、硬科技投资团队
**技术路线：** 模块化单体 + 公共产业数据库 + 机构私有知识库 + 可审计 AI Agent
**首期目标：** 完成从产业企业发现到机构内部项目初筛的可验证闭环

# 第一部分：产品定义

## 1.1 产品愿景

构建面向投资机构的 AI 投资情报基础设施，将公开产业信息、机构内部历史资料、投资策略与 AI 工作流整合为统一工作平台。

产品不仅回答投资人员提出的问题，还应支持发现企业、整理证据、匹配投资策略、分析潜在项目、生成研究成果，并把经过人工确认的信息沉淀到机构自己的知识体系中。

## 1.2 产品定位

产品由三个核心部分构成：

1. **Industry Intelligence：公共产业情报平台**
   - 企业数据库
   - 产业链与技术路线
   - 企业产品、技术与经营信号
   - 企业搜索、筛选、画像与监控
2. **Private Knowledge：机构私有知识平台**
   - 历史投资项目
   - BP、尽调材料、访谈纪要
   - 投资报告与投决材料
   - 投资策略、研究方法论、行业判断
   - 项目经验与历史决策记录
3. **PE AI Workbench：AI 投资工作台**
   - 企业发现 Agent
   - 企业画像 Agent
   - 产业研究 Agent
   - 项目匹配 Agent
   - BP 初筛 Agent
   - 尽调问题生成与报告辅助

三者共享基础设施，但数据权限和业务边界必须明确。

## 1.3 产品核心原则

### 原则一：数据资产优先

产品的长期竞争力来自持续积累的高质量产业数据、企业关系、技术信息、历史变化和客户工作流，而不是简单调用大模型。

### 原则二：公共数据与私有数据分离

公共产业数据可按授权范围服务多个客户。机构私有数据只允许该机构授权的用户访问，不得用于其他客户的检索、回答、训练或推荐。

### 原则三：所有关键事实均可追溯

关键企业事实、财务数字、融资事件、技术参数、判断依据，应关联原始来源、文档位置或证据记录。

### 原则四：事实、推断和未知必须分开

系统需要明确区分：

- 已有来源支持的事实
- 基于事实的分析推断
- 尚未核实的信息
- 不存在或无法获取的数据

### 原则五：AI 辅助，不自动决策

V1.0 不自动执行投资决策、投决审批、资金划拨、交易执行或法律承诺。

### 原则六：先完成一个真实工作闭环

首期不追求全行业数据覆盖和复杂 Agent 自治，优先实现一个细分产业的企业发现、证据检索、机构匹配和初筛报告闭环。

# 第二部分：用户与使用场景

## 2.1 目标用户

| 用户角色 | 核心需求 | 主要功能 |
| --- | --- | --- |
| 投资合伙人 | 判断投资机会、了解行业和候选项目 | 企业发现、项目匹配、产业研究 |
| 投资总监 | 项目筛选、行业研究、尽调推进 | 企业画像、项目初筛、报告草案 |
| 投资经理 | 搜集资料、分析企业、制作材料 | 搜索、证据检索、BP 分析 |
| 研究员 | 维护产业数据库、跟踪企业变化 | 企业档案、产业地图、信息核验 |
| 知识管理员 | 管理内部知识与权限 | 文档入库、标签、权限和版本 |
| 系统管理员 | 管理用户、模型、配置与审计 | 租户管理、权限、模型配置、日志 |

## 2.2 核心使用场景

### 场景 A：寻找潜在投资标的

用户输入：

> 寻找中国境内具备先进封装混合键合技术能力、处于商业化推进阶段、尚未上市的潜在投资企业。

系统执行：

1. 解析行业、技术、地域、阶段与上市状态等筛选条件。
2. 从公共产业数据库检索候选企业。
3. 补充企业产品、技术、客户、合作、招聘、专利等公开信号。
4. 对每家候选企业生成证据支持的企业画像。
5. 根据机构投资策略匹配候选企业。
6. 输出候选企业列表、匹配理由、证据与待核实问题。
7. 由投资人员决定是否创建项目。

### 场景 B：使用机构历史经验辅助项目判断

用户上传一家半导体设备公司的 BP。

系统执行：

1. 解析 BP 并提取企业、产品、市场、技术、客户、财务与融资信息。
2. 检索机构历史项目和相关研究报告。
3. 找出历史项目中可比较的技术路线、商业化阶段、竞争对手和风险。
4. 生成项目初筛报告草案。
5. 将每个关键结论关联对应证据。
6. 对缺失数字、冲突信息和未经核实的说法进行标记。
7. 由投资经理审核、修改并导出。

### 场景 C：产业研究

用户输入：

> 分析中国先进封装设备产业链，并梳理混合键合相关设备、关键工艺、主要企业及产业化进展。

系统输出：

- 产业链结构
- 关键技术环节
- 细分市场与技术路线
- 企业清单与企业画像
- 竞争格局
- 公开市场信号
- 关键风险与待核实事项
- 引用来源和资料更新时间

### 场景 D：持续跟踪企业

投资人员建立企业观察清单，系统根据合法获取的新增公开信息，记录企业变化，包括产品发布、专利、公告、合作、招聘、招投标等。

V1.0 先实现手动刷新和定时任务基础能力。自动通知、复杂事件规则与多渠道推送可放入后续版本。

## 6.4 事实与推断

所有 AI 生成的重要内容应标注类别：

- fact：来源直接支持的事实
- inference：基于事实的推断
- unverified：待核实内容
- unknown：目前未知
- conflicting：来源存在冲突

例如：

“企业官网显示其推出混合键合设备”可以作为有来源支持的事实。

“企业已经具备稳定量产能力”不能仅由产品发布推导得出。若没有客户验证、量产信息或其他可靠证据，应标注为未知或待核实。

## 6.5 数据更新机制

V1.0 支持：

1. 手工录入。
2. CSV/Excel 批量导入。
3. 授权 API 导入。
4. 经许可的公开来源采集。
5. 文档上传与结构化提取。
6. 人工核验和纠错。

每次数据更新应保留：

- 更新来源
- 更新日期
- 原始值
- 新值
- 变更原因
- 核验状态
- 操作用户或任务 ID

不得静默覆盖关键事实。

## 6.6 企业去重策略

优先匹配：

1. 统一社会信用代码
2. 官方登记名称
3. 官网域名
4. 企业历史名称
5. 地址与其他辅助字段

仅名称相似不能直接自动合并。

系统应支持：

- 自动识别疑似重复企业
- 人工确认合并
- 合并历史记录
- 取消错误合并
- 保留源数据与原始标识

# 第七部分：机构私有知识库

## 7.1 核心目标

为每家投资机构建立独立的私有知识空间，支持机构内部资料检索、项目分析和历史经验复用。

私有数据包括：

- BP
- 投资报告
- 尽调报告
- 访谈纪要
- 财务模型
- 投决材料
- 投资策略
- 内部会议纪要
- 历史项目结论

## 7.2 文档处理流程

``` text
Upload
  |
  v
Permission Check
  |
  v
File Validation & Hash
  |
  v
Object Storage
  |
  v
Document Parsing
  |
  v
Text & Table Extraction
  |
  v
Chunking & Metadata
  |
  v
Embedding
  |
  v
PostgreSQL / pgvector Index
  |
  v
Ready for Retrieval
```

每个阶段都应保存状态，支持失败重试和错误定位。

文档状态：

- uploaded
- validating
- parsing
- chunking
- embedding
- indexed
- failed
- deleted

## 7.3 文档切分要求

切分应考虑：

- 标题层级
- 段落结构
- 页码
- 表格边界
- 文档类型
- 原始位置
- 章节名称

每个 chunk 至少包含：

- chunk\_id
- document\_id
- organization\_id
- project\_id（允许为空）
- text
- page\_number
- section\_name
- chunk\_index
- content\_hash
- embedding
- source\_metadata

财务表格与关键数字不应仅依赖普通文本切分。必要时需要单独提取为结构化记录，并保留原始表格位置。

## 7.4 检索流程

推荐采用混合检索：

1. 用户身份验证。
2. 检查机构权限。
3. 检查项目权限。
4. 过滤可访问文档。
5. 执行关键词检索。
6. 执行向量检索。
7. 合并并排序候选证据。
8. 可选重排序。
9. 返回原始片段与位置。
10. 将证据交给 Agent 生成答案。

检索结果必须携带来源元数据，不能只返回没有来源的文本。

## 7.5 多租户安全

必须满足：

- 每条私有业务记录具有 organization\_id。
- 每个文档具有明确的租户归属。
- 每个检索请求先进行服务端权限验证。
- 向量检索必须在可信服务端执行租户与项目过滤。
- 数据库可使用 Row-Level Security 作为额外防护。
- 文件下载必须重新验证权限。
- 后台任务必须携带租户上下文。
- 日志不得记录完整敏感文档内容。
- 跨租户测试必须覆盖搜索、下载、导出、缓存和任务执行。

不能仅依靠前端隐藏按钮或向量数据库的 metadata filter 来实现安全隔离。

# 第八部分：AI Agent 设计

## 8.1 总体原则

Agent 不是完全自主的虚拟投资人，而是有明确输入、输出、步骤、证据要求和审核边界的工作流。

每个 Agent 必须定义：

- 输入 Schema
- 输出 Schema
- 数据权限
- 工具权限
- 可访问的数据源
- 提示词版本
- 执行步骤
- 错误处理
- 评测标准
- 人工审核点

## 8.2 Agent 一：企业发现 Agent

### 输入

``` json
{
  "industry": "半导体设备",
  "technology": ["混合键合"],
  "region": ["中国大陆"],
  "listing_status": "unlisted",
  "commercialization_stage": ["pilot", "commercial"],
  "limit": 50
}
```

以上为示例结构，真实取值必须与系统枚举保持一致。

### 执行步骤

1. 解析用户搜索意图。
2. 转换为结构化筛选条件。
3. 检索公共企业数据库。
4. 补充技术与产业标签。
5. 按匹配条件排序。
6. 生成每家企业的入选理由。
7. 返回候选列表与证据。

### 输出

- 企业列表
- 匹配条件
- 入选理由
- 支持证据
- 不确定字段
- 待核实事项

排序应尽量采用可解释规则。V1.0 不应输出伪精确的投资成功概率。

## 8.3 Agent 二：企业画像 Agent

### 输入

- company\_id
- 可用公共数据
- 用户权限允许访问的来源

### 输出结构

``` json
{
  "company_id": "uuid",
  "summary": "企业概况",
  "products": [],
  "technologies": [],
  "industry_position": [],
  "public_signals": [],
  "risks": [],
  "unknowns": [],
  "evidence_ids": [],
  "last_updated_at": "timestamp"
}
```

### 要求

- 事实必须关联证据。
- 不得编造客户、收入、融资额、市场份额。
- 证据不足时输出 unknown。
- 对相互矛盾的来源分别展示。
- 标明数据时间，避免将历史状态描述为当前状态。

## 8.4 Agent 三：产业研究 Agent

### 执行步骤

1. 解析研究问题。
2. 生成研究提纲。
3. 检索公共产业数据库。
4. 检索授权的公开来源和研究资料。
5. 建立证据集合。
6. 按章节生成报告。
7. 对关键结论检查证据完整性。
8. 输出报告草案与参考来源。

报告章节建议：

- 研究范围
- 产业链结构
- 技术路线
- 市场与需求
- 主要企业
- 竞争格局
- 商业化进展
- 产业风险
- 待核实问题
- 数据局限性
- 参考资料

## 8.5 Agent 四：项目匹配 Agent

### 输入

- 目标企业
- 机构投资 Thesis
- 可访问的机构历史项目
- 可访问的机构研究报告
- 公共产业数据

### 匹配维度

- 行业符合度
- 技术路线符合度
- 商业化阶段符合度
- 地域符合度
- 投资阶段符合度
- 机构明确的排除条件
- 与历史项目的相似性

### 输出

- 匹配理由
- 不匹配因素
- 关键证据
- 与历史项目的可比性
- 需要进一步核实的问题
- 数据缺口

系统必须区分“与历史项目相似”和“投资结果可能相似”。历史相似性不代表未来投资收益。

## 8.6 Agent 五：BP 初筛 Agent

### 输入

- project\_id
- 已授权的项目文件
- 公共企业数据
- 机构私有知识库检索结果
- 机构初筛模板

### 执行步骤

1. 检查文档是否成功解析。
2. 提取企业基本信息。
3. 提取产品与技术路线。
4. 提取市场、客户、商业化信息。
5. 提取财务与融资数字。
6. 检索机构内部历史项目。
7. 识别潜在竞争对手和可比企业。
8. 生成初筛报告草案。
9. 登记关键数字和证据。
10. 检查缺失数据、冲突和引用。
11. 进入人工审核。

### 报告结构

1. 项目基本情况
2. 企业与团队
3. 产品与技术
4. 市场与竞争格局
5. 商业化进展
6. 财务与融资情况
7. 与机构投资策略的匹配程度
8. 潜在优势
9. 主要风险
10. 尽调问题
11. 数据缺口
12. 证据与来源
13. 初步结论及其局限性

AI 只能形成分析草案，不能代替投委会判断。

## 8.7 Agent 六：尽调问题生成

根据项目所属行业、阶段、商业模式和现有证据生成问题。

问题分类：

- 技术真实性
- 技术成熟度
- 产品性能
- 客户验证
- 量产与交付
- 供应链
- 市场空间
- 竞争格局
- 财务
- 股权结构
- 知识产权
- 合规与法律
- 融资计划
- 退出路径

每个问题应包含：

- 问题本身
- 提问原因
- 对应风险
- 当前已知信息
- 缺失证据
- 建议验证方式
- 优先级

# 第九部分：关键数字与报告质量闸

## 9.1 设计目的

投资报告中常见问题是数字无来源、引用不准确、不同来源数字冲突以及模型补齐未知数据。

V1.0 必须为关键数字建立单独的登记和核验机制。

## 9.2 KeyMetric 模型

建议字段：

- id
- organization\_id
- project\_id
- metric\_name
- metric\_value
- unit
- currency
- period
- metric\_type
- evidence\_id
- source\_document\_id
- verification\_status
- reviewer\_id
- reviewed\_at
- notes
- created\_at
- updated\_at

数字类型包括：

- revenue
- gross\_margin
- shipment\_volume
- capacity
- market\_size
- financing\_amount
- valuation
- customer\_count
- market\_share
- other

## 9.3 核验状态

- unverified
- verified
- conflicting
- rejected
- not\_applicable

## 9.4 导出规则

正式报告导出前检查：

1. 是否包含未经核验的关键数字。
2. 关键结论是否有证据支持。
3. 是否存在来源冲突。
4. 是否存在无来源的外部事实。
5. 是否将推断描述为事实。
6. 是否存在缺失数据被模型补全的情况。
7. 是否存在不具备访问权限的引用。

报告状态建议：

- draft：草稿
- review\_required：需要审核
- approved\_for\_export：允许正式导出
- exported：已导出

正式导出规则应可配置。

默认情况下，未核验关键数字不能进入正式报告。对于允许保留的未知数据，应明确标注“待核实”或“不适用”，不能用估计值静默补全。

# 第十二部分：安全、合规与治理

## 12.1 身份认证

V1.0 至少实现：

- 登录认证
- 会话管理
- 密码安全存储
- 用户停用
- 机构成员管理
- 角色与权限控制

生产部署可进一步接入企业 SSO、多因素认证与统一身份管理。

## 12.2 权限控制

权限校验必须在后端执行。

建议采用 RBAC 与资源级授权结合的方式。

主要权限：

- organization:read
- organization:manage
- project:read
- project:write
- document:read
- document:upload
- document:delete
- agent:run
- report:review
- report:export
- audit:read
- system:manage

对于项目级敏感资料，除机构权限外，还需检查用户是否具备相应项目访问权限。

## 12.3 模型数据安全

默认规则：

1. 原始项目资料优先在本地或受控环境解析。
2. 默认不将完整原始文件发送到外部模型。
3. 外部模型调用前进行数据分类和授权检查。
4. 对可脱敏的必要片段，按配置决定是否允许外发。
5. 私有资料不得用于其他客户的上下文。
6. 不将客户资料用于模型训练，除非存在明确、独立的授权与合同依据。
7. 保存模型调用的必要审计元数据。
8. 对敏感字段、密钥和个人信息采取最小化处理。

需要注意：使用外部模型 API 时，数据是否留存、是否用于训练、处理区域及相关保障措施取决于具体服务商、产品协议和配置，不能仅凭“API 调用”推定数据绝不留存。

## 12.4 数据来源合规

所有进入公共数据库的数据应有来源和许可记录。

需要检查：

- 来源网站或数据库的使用条款
- API 授权范围
- 数据抓取限制
- 商业使用权限
- 数据再分发权限
- 个人信息处理要求
- 著作权和数据库权益
- 删除、纠错与投诉机制

公开可访问不等于可以无限制抓取、存储、加工和商业转售。

## 12.5 审计日志

关键操作至少记录：

- 登录与权限变化
- 文档上传、下载与删除
- 项目创建和修改
- Agent 运行
- 私有知识检索
- 报告审核
- 正式导出
- 数据导入和合并
- 模型配置变更
- 管理员操作

日志应记录操作者、租户、时间、资源、动作、结果和关联任务 ID。避免把完整敏感文档内容直接写入日志。

# 第十三部分：模型适配与成本控制

## 13.1 Model Gateway

所有模型调用通过统一接口，不允许业务代码直接散布不同模型服务商的调用逻辑。

统一能力包括：

- chat completion
- structured output
- embedding
- reranking（可选）
- token usage
- latency
- retry
- timeout
- error classification
- provider configuration

## 13.2 模型分工

| 任务 | 推荐方式 |
| --- | --- |
| 文档解析 | 本地确定性解析工具优先 |
| 字段提取 | 结构化输出模型 |
| 企业搜索 | 数据库检索优先，模型负责意图解析 |
| 语义检索 | Embedding + 向量数据库 |
| 企业画像 | 检索增强生成 |
| 产业研究 | 分章节检索与生成 |
| BP 初筛 | 显式工作流 + 证据检索 |
| 报告质量检查 | 规则检查优先，模型辅助 |
| 权限校验 | 后端代码，不交给模型 |

## 13.3 成本控制

需要记录：

- 模型调用次数
- 输入与输出 token
- 任务耗时
- 失败重试次数
- 单次任务估算成本
- 单个租户使用量

可配置：

- 每机构用量上限
- 每任务 token 上限
- 并发限制
- 重试上限
- 超时
- 模型降级策略

不能在没有记录的情况下无限重试模型调用。

# 第十五部分：MVP 验收标准

以下是首期验收目标，具体性能指标需在试点环境基准测试后校准。

## 15.1 公共数据库

- 支持企业基本信息创建、查询、修改和导入。
- 支持行业、技术、地域和上市状态筛选。
- 企业详情可显示来源与更新时间。
- 可记录企业别名和疑似重复记录。
- 关键企业事实可关联证据。
- 不存在来源的数据字段允许为空。

## 15.2 私有知识库

- 支持规定格式的文档上传。
- 文档解析状态可查询。
- 支持关键词和语义检索。
- 检索结果包含文档、页码或其他可定位信息。
- 用户只能访问其有权查看的文档。
- 删除文档后，相关索引与可访问内容应按设计清理。

## 15.3 AI Agent

- 企业发现可以返回候选企业与入选理由。
- 企业画像包含证据与未知字段。
- 项目匹配能够结合机构投资策略和授权的私有资料。
- BP 初筛可以输出规定结构的报告草案。
- 尽调问题可以关联现有信息缺口。
- 模型失败时任务可进入明确的失败状态。
- 关键事实不能仅凭模型输出直接写入已核验数据。

## 15.4 报告质量

- 报告可以定位到原始证据。
- 关键数字具有登记和核验状态。
- 存在冲突时能够展示冲突。
- 未核验的关键数字不能静默进入正式报告。
- 正式导出需要通过规则检查。
- 所有审核和导出操作均可审计。

## 15.5 安全性

- 跨租户读取测试全部通过。
- 跨项目越权测试全部通过。
- 后端执行权限检查。
- 外部模型调用符合租户配置。
- 关键操作有审计记录。
- 密钥与敏感配置未提交到代码仓库。

# 第二十部分：V1.0 产品决策总结

V1.0 的目标不是做一个覆盖所有投资场景的超级平台，而是验证一个有商业价值、可复制、可持续积累数据资产的工作闭环。

**产品闭环：**

公共产业数据库 → 企业发现 → 企业画像 → 机构私有知识检索 → 投资策略匹配 → BP 初筛 → 证据核验 → 人工审核 → 项目知识沉淀。

**产品壁垒：**

1. 高质量的垂直产业数据。
2. 可追溯的企业事实与证据体系。
3. 严格隔离的机构私有知识库。
4. 贴合真实投资工作的 Agent 工作流。
5. 客户持续使用后形成的机构专属知识资产。
6. 通过 FDE 实施不断提炼出的标准化能力。

**首期执行顺序：**

先搭建基础架构和多租户权限，再建设公共企业数据库与私有知识库，然后开发企业发现、企业画像、项目匹配和 BP 初筛，最后完成报告质量闸、评测和客户试点。

**最终判断标准：** 投资团队是否愿意把它纳入日常项目发现和初筛工作流，并为可量化的效率提升、产业情报质量和机构知识沉淀持续付费。

文档中尚未确定的企业数据供应商、授权范围、具体模型版本、实际数据规模、生产部署形态和最终报价，应在试点阶段根据真实条件确认，不应在开发中自行假设为已解决。
