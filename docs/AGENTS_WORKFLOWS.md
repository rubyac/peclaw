# AI 研究工作流（阶段五）

登录后进入 `/agents`，选择有效机构与已获授权项目。五种工作流分别为企业发现、企业画像、项目匹配、BP 初筛、尽调问题。只产生待人工审核的结构化研究草案；没有阶段六的正式报告审批、关键数字质量闸或 Word/Markdown 导出。

## 模型配置与真实调用

默认 `MODEL_PROVIDER=disabled`，不会调用外部生成模型。页面显示“尚未配置生成模型”并禁用提交；API 仍可登记任务，worker 会明确记录 MODEL_NOT_CONFIGURED 失败，不生成占位分析。

部署管理员在运行环境的秘密变量中配置，勿将密钥提交到仓库或粘贴在聊天中：

```dotenv
MODEL_PROVIDER=openai_compatible
MODEL_BASE_URL=https://api.deepseek.com/v1
MODEL_NAME=deepseek-chat
# MODEL_API_KEY 通过部署平台 secret 注入
MODEL_TIMEOUT_SECONDS=40
MODEL_MAX_OUTPUT_TOKENS=4000
MODEL_ORG_DAILY_TOKEN_LIMIT=200000
MODEL_ORG_CONCURRENCY=1
```

端点只接受不含凭据/查询参数的 HTTPS URL，调用 `/chat/completions`，使用 JSON object response_format、temperature=0、非流式响应；在服务商返回后再执行本地 Pydantic Schema 校验。不是假设服务商支持 JSON Schema strict 模式。兼容端点必须支持该协议；不会自动切到其他厂商、降级成无结构文本或携带资料跟随重定向。默认 DeepSeek 地址仅是配置示例，未配置真实凭据、价格或认证通过保证。提供方与模型名称不由浏览器指定。

完整保留平台代理与 TLS 验证。Codex 当前网络策略只放行开发依赖站点，没有模型身份凭据；本阶段没有真实模型连通性/效果记录。若在此环境启用真实模型，需要通过正式环境配置流程加入目标域名和 secret，不能通过修改本地策略文件、直连或关闭证书校验绕过。

配置后重建/重启 API 与 worker 以读取环境。全容器自动运行 `agent-worker`；本机运行 `cd services/api && uv run python -m app.agent_worker`。只显示“已配置”，不冒充连接测试已通过。

## 输入、检索和边界

- 企业发现：明确结构化公共筛选（名称、行业/技术 ID、地域、上市/商业化/融资阶段等，API Schema 详见 `/docs`），按数据库确定性顺序选最多 20 家；模型解释这些候选，不拥有扩展候选或网络采集权限。研究问题不会被偷偷转换为未经确认的数据库筛选。
- 企业画像：必须选择公共 company_id，收集显式基础字段和最多 6 条公共证据，产出企业、产品技术、产业位置与风险四组陈述。
- 项目匹配：公司与用户明确输入的投资 Thesis 必填，可加本项目明确选中的授权资料，区分 fit/mismatch/comparability/gaps。不自动访问其他项目，不能把历史相似性描述成收益概率。
- BP 初筛：至少一份当前项目已完成索引且可读取的私有文档；分为企业团队、产品技术、市场竞争、商业化、财务融资、策略匹配、风险、缺口八组陈述。财务数字仍是未经核验的模型草案，不等于阶段六数字核验。
- 尽调问题：技术、商业、财务、法律四组，至少一个问题，每题包括原因、风险、已知信息、缺失证据、验证方式和优先级。可以没有证据，此时只允许 unknown 陈述，不假装检索有结果。

每个任务最多明确选择 10 份文件，每份取前 8 个已索引片段。公共与私有材料均有硬性上下文上限，过大返回 CONTEXT_LIMIT，而非静默遗漏后声称覆盖全文。当前是有界确定性证据收集，不是完整长文财务提取或跨项目 RAG；结果须明确不完整性。

提交前对所有选中文档逐一重新授权。任务保存证据 ID、版本、摘要，不保存完整检索上下文副本；模型返回的结构化草案按项目私有存储。执行前再次收集并与提交时证据引用集合/摘要比较，变更不自动替换，返回 EVIDENCE_CHANGED。调用前、提交结果前、每次详情读取均重新检查有效账号、机构、项目与原文 ACL。私有原文默认未核验，受限文档没有管理者旁路。

任务输入和结果仅发起人可见，实际项目权限仍必须有效；机构管理员、其他项目成员或公共目录维护员没有隐式读取权限。任务列表只返回状态、版本、时间、次数等有限元数据，不包含问题、Thesis、证据或草案。已撤销原文资格的任务详情不能用缓存的生成内容旁路读取。合法发送后服务商可能已持有原文；撤销权限无法追回先前已发送内容，需另行核对供应商保留政策。

界面说明提交将发送问题与 Thesis；明确选中私有文档必须额外勾选有权向已配置模型服务发送，后端也要求 allow_private_to_model=true。整个流程没有自由工具调用、网页访问、SQL 生成、代码执行或发邮件能力，文件内容只是用户角色中的不可信 evidence。

## 输出与版本

五类提示词位于 `app/agents/prompts.py`，各有 `kind@1.0.0`、完整模板 SHA-256 和固定章节 key。任务固定版本/摘要，旧模板不可用时拒绝执行；新版本应保留旧模板注册表后再扩展，不可修改模板冒充相同历史内容。

输出必须符合 AgentResult、Claim、Section、DiligenceQuestion Schema。每条非 unknown 陈述必须引用上下文存在的证据；fact 只能引用 classification=fact 且 verification=verified 的来源。候选只能来自已检索公司，工作流和全部章节 key 必须匹配。伪造引用、少章节、未核验材料冒充事实、截断响应和非法 JSON 均失败，不展示部分无效结果。

服务器校验引用存在和来源状态，不证明语义蕴含、数值、时间推断或投资判断正确。模型自由文本仍可能错误，界面持续标示“待人工审核”。引用正文及已有来源冲突状态可供人工对照；没有自动解决来源冲突或取代审核。页面中的未知、待核验、推断、冲突不应当作统一事实展示。

## 状态、重试与费用

状态：queued → retrieving → calling → validating → review_required；或 failed/cancelled。任务有机构/项目/发起人、唯一幂等键、次数、错误码、claim token、租约。提示词、状态与最终结果持久化在 PostgreSQL，不依赖内存队列。领取用 SKIP LOCKED，检索租约 120 秒，调用租约 300 秒；过期任务可恢复，累计最多三次，耗尽后转失败。模型 HTTP 不做隐藏重试；手动重试和进程恢复均计入任务次数。输入或证据变更应新建任务，不能复用旧幂等键悄悄修改。

每次调用前锁定机构行，检查并发和当天用量，建立 ModelCall reservation 后才发请求。取消的进行中请求仍占用并发位，直到调用结束或保守租约过期；不会因为界面取消就重复占满外部服务。取消作废 claim token，迟到响应不发布；无法保证已发送请求立即停止或不计费。

每日预算按 UTC 日重置。采用完整请求文本 UTF-8 字节数 + 最大输出 token 的保守预留，失败/中断请求也保留额度，防止未知计费后无限重试；如服务商报告更多 tokens，则提高已占额度。它不是账单或精确 tokenizer 估算。每机构相同配置限额，暂没有分别编辑机构套餐的 UI；最多 100 个待处理任务，列表/API 可分页。

ModelCall 记录提供方、模型、尝试次数、状态、预留额度、实际输入/输出 token（服务商缺失则 unknown）、耗时和受控错误码，不保存 API key、原始响应或正文。401/403、429、超时、网络/5xx、协议/Schema/引用问题分开记录，不把服务商错误 body 写入用户响应。

可选 `MODEL_INPUT_PRICE_PER_MILLION` 与 `MODEL_OUTPUT_PRICE_PER_MILLION` 为每百万 token 的 USD 费率，均有效且有实际用量时才计算 estimated_cost_micros；未配置显示未知，不擅自填服务商价格或零费用。审计仅记录动作、ID、kind、提示词版本、次数、错误码等，不保存私有问题、Thesis 或正文。
